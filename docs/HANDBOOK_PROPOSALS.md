# Handbook proposals from Thalia

Generic things Thalia had to add or work around. Each would make the next app cheaper. None of
them is changed in `Vendor/BinisoftKit` or `scripts/ci` here – they belong in the handbook.

| # | Proposal | Why (what Thalia did) | Where |
|---|---|---|---|
| 1 | **Localizable kit strings** (German at least): use `String(localized:bundle: .module)` / `LocalizedStringResource` and ship `de.lproj` in the kit | The kit mixes `LocalizedStringKey` literals (translatable from the app) with plain `String`s that can't be translated: tour coach ("Nice, that's it!", Skip/Next/Done from `TourProgress.primaryTitle`), `Appearance.title`, `DataSection.standard`, `SyncState` summary/account texts, `CreateSheet` default title. Thalia added `App/Resources/de.lproj/Localizable.strings`, its own German coach card, appearance picker and data facts | kit `TourCoach.swift`, `Tour.swift`, `Theme.swift`, `SyncSettings.swift`, `SyncStatus.swift` |
| 2 | **`DayKey` / `WeekKey` (ISO 8601) in BinisoftKitCore** | Day and week values without time zones, week 53, German labels – any app with weekly planning or streaks needs them; Calendar-based code differs between devices/time zones | Thalia `Packages/ThaliaCore/Sources/ThaliaCore/Calendar.swift` (tested) |
| 3 | **Key-based SwiftData models as a documented option** + `Array.latest(by:modified:)` in the kit | No relationships, records link by stable keys; duplicates created offline on two devices resolve as "latest change wins". Sync order never matters | Thalia `Shared/Models.swift`; CONVENTIONS §6 |
| 4 | **Generate `cloudkit/schema.ckdb` from the models** and check it in CI | Thalia's schema (13 record types) is generated from `Shared/Models.swift` by `tools/schema-from-models.py` – a `scripts/ci/schema-from-models.py` + a CI step "schema matches models" would prevent missing fields before Production deploys | ci/scripts |
| 5 | **Reminders in the kit**: `ReminderSettings` (Core, testable) + scheduler with deep-link routing and a notification delegate | Morning / evening / weekly / "block over" reminders, Apple weekday conversion (Sunday = 1) tested on Linux | Thalia `ThaliaTour.swift` (ReminderSettings), `App/Sources/Services.swift` |
| 6 | **Small platform helpers**: `compactListSections()`, `decimalKeyboard()`, `numberKeyboard()` | `listSectionSpacing` and `keyboardType` don't exist on macOS | kit `Platform.swift` |
| 7 | **Pitfall: sheets presented from a sheet** need `.environment(app)` / Observable services passed again | Thalia's close-day sheet opens measurement and item sheets locally (the app-wide sheet slot is taken) | CONVENTIONS §8 |
| 8 | **Pitfall: the first push to an empty repo doesn't start `ci.yml`** | With `paths-ignore`, GitHub has no base to compare when `main` is created; only `testflight.yml` (no path filter) ran. Fix: start CI manually after `new-app.sh`, or add a note in SETUP 1.2 | ci/workflows/ci.yml, SETUP_CHECKLIST 1.2 |
| 9 | **`local-check.sh`: start the Docker daemon when the CLI exists but no daemon runs** (`sudo -n dockerd &`) | In the cloud session Docker was installed but not running; `make check` would have fallen back to "install a toolchain" | ci/scripts/local-check.sh |
| 10 | **Setup checklist artifact template** with shared ticks (claude.ai `db` capability) | Thalia's checklist page lets the owner tick steps and Claude tick them via the database; a template HTML in the handbook would make every app's checklist identical | tools/ or ci/ |
| 11 | **`ImportPlan` removals** (records of a re-imported scope that the file no longer has) | Re-importing a revised weekly plan must drop items; Thalia built `ImportPreview.removedItems` around the kit's plan | kit `Import.swift` |
| 12 | **`AIImportPrompt` language and multi-type formats** | The kit prompt is English and single-record-type; Thalia's planning prompt is German, defines 12 row types and embeds the last week's report | kit `Import.swift`, Thalia `Reports.swift` (`PlanPrompt`) |
| 13 | **HealthKit read-only suggestions pattern** (device-only adopted values, entitlement only on the iPhone App ID, **both** `NSHealthShareUsageDescription` and `NSHealthUpdateUsageDescription`) | Same rule as George, but for *reading* Health as suggestions. TestFlight run 7 failed at export: Apple requires the *update* purpose string with the HealthKit entitlement even when the app never writes. SETUP_CHECKLIST could list HealthKit as a common extra capability with the exact click path | SETUP_CHECKLIST 2.2, CONVENTIONS §8 (pitfall), template Info.plist comment |
| 14 | **Live Activity for a running timer** (attributes in `Shared/`, UI in the widget extension) | No extra portal step, but `NSSupportsLiveActivities` and the shared attributes file are easy to forget | template / docs |
| 15 | **Session branch vs. "push to main"** | The cloud session names a feature branch; HOW_WE_WORK says push to `main`. Thalia pushes both. One sentence in HOW_WE_WORK §2 would settle it | HOW_WE_WORK §2 |
| 16 | **Check App ID capabilities and App Group assignments before the first archive** | TestFlight run 6 failed because the widgets App ID had App Groups switched on but no group assigned ("profile doesn't match … application-groups"). A read-only `asc.py` check of `bundleIdCapabilities` for every target (or a clearer SETUP 2.5 wording: "Configure is a separate click after Register") would catch it in seconds instead of a Mac archive | ci/scripts/asc-status.py, SETUP_CHECKLIST 2.5 |
| 17 | **SwiftUI pitfalls that only a Mac build shows** (Linux `swiftc -parse` passes them): arithmetic with several `??` in one view expression ("unable to type-check in reasonable time" – move it into a small typed helper), `Section("Title") { } footer: { }` does not exist (use `Section { } header: { } footer: { }`), `if`/`else` assigning a `let` inside a `body` is read as view building (use a helper function), `Optional(x)` on a value that is already optional | Thalia v2 CI runs 6–7; a short list in CONVENTIONS §8 and a reviewer pass for these before pushing saves Mac minutes | CONVENTIONS §8 |
| 18 | **Control Center button pattern** (iOS 18+): an `AppIntent` with `openAppWhenRun` in a `Shared/` file compiled into app **and** widget extension, plus a `ControlWidgetButton` in the `WidgetBundle`; the intent sets a pending route the app reads at launch | Thalia `Shared/RouteIntents.swift`, `Widgets/Sources/ThaliaWidgets.swift` (`PowerHoursControl`) – no portal step, worth a template slot | template / docs |
| 19 | **Re-import archives instead of overwriting** (`replacedWeeks` in the preview, a CSV snapshot model, restore swaps back) and **in-app plan changes listed in the next AI prompt** ("dauerhaft übernehmen" / "nur diese Woche") | Generic for any app whose plan comes from an AI round-trip | kit `Import.swift`, Thalia `TrackerStore+Import.swift`, `PlanChangeRecord` |
